# OneCode 人工测试清单

只收录**单元测试覆盖不到、必须真人在真机验证**的项。逻辑、解析、存储层已由 `src/OneCode.Tests` 覆盖，怀疑这类能力有问题请补单测，不要往这里加条目。人工要验的只有四类事：

- **真实终端**的绘制结果与手感（多终端差异、宽字符对齐、滚动、缩放）
- **发布产物**的真实运行（脱离 SDK 与源码、Release 日志行为）
- **真实进程生命周期**（强杀、残留进程、退出码、跨进程重启恢复）
- **真实外部系统与真实时序**（MCP / LSP / git / cron 到点 / 断网、真实 LLM 流式）

## 两种用法

| 场景 | 跑什么 |
|---|---|
| 日常自测 | 改了哪个模块，只跑该模块表格中标 **●** 的行 + 文末「收尾检查」 |
| 发布验收 | 从 §1 逐项跑到 §11（● 和 ○ 都要）；主链路 §1 → §4 不通过就不用继续 |

频度标记：**●** = 该模块的主路径，日常改完必查；**○** = 边缘/深度场景，仅发布验收逐项跑。

## 环境与启动

| 方式 | 命令 | 说明 |
|---|---|---|
| VS | 直接 F5 启动 `OneCode.Cli` | 自动带 `--cwd E:\OneCode\.dev-workspace`，被 git 忽略的沙盒目录，放心让 agent 改文件 |
| 命令行 | `dotnet run --project src/OneCode.Cli -- --cwd <路径>` | 要在真实仓库测时用 |
| 发布验收 | `dotnet publish src/OneCode.Cli/OneCode.Cli.csproj -c Release` 后**从输出目录启动** | §1 及全量验收用 |

日志级别只由构建模式决定，没有运行时开关：

| 构建 | 级别 | 控制台 | 文件 |
|---|---|---|---|
| Debug | `Debug` 及以上 | 多行 + 时间戳 + 作用域 | `~/.onecode/debug/<id>.log` |
| Release | `Warning` 及以上 | 单行 | `~/.onecode/debug/<id>.log` |

Debug 构建启动时把日志文件路径打印到 stderr（`Log file: ...`）；Release 构建正常启动不打印任何非 warning/error 输出，文件位置见 [settings.md](../settings.md)。

终端以 Windows Terminal 100 列为基准；另在 ConHost / VS Code 集成终端各抽查 §11。

| ● | 切换模式后回看消息区 | 已有对话完整保留，模式切换不清空历史 | |

| ○ | `/review`（无 `--focus`） | 三视角并行输出一份聚合去重报告；`--focus security` 单视角流式正常 | |
| ○ | 自定义子代理 | 在 `.onecode/agents/` 放一个 `*.md`（name/description/allowed_tools + 正文），重启后 Agent 工具 description 可见、按名派工生效；坏 frontmatter 显式报错 | |
| ○ | 子代理嵌套派工 | 让子代理尝试调用 `Agent` 工具 | 工具面对子代理不可见（深度上限 1） | |

| ○ | 子代理预算收尾 | 派一个子任务并把 `agents.defaults.maxTurns` 设为 2 | 到达上限后子代理收尾总结而非持续报错，结果带 `[PARTIAL]` 标记 | |
| ○ | GOAL 模式提交自主目标，中途 `Esc` 后 `/resume` | 循环过程与预算消耗可见；中断后可跨进程恢复 Goal 运行 | |
| ○ | GOAL 目标含 subTasks 并行步骤（分解器产出 2-5 个互不重叠子任务） | 任务并行执行、进度按子任务可见；全部成功则该步完成 | |
| ○ | GOAL 并行步骤部分失败 → replan | 失败步标记为被取代、成功兄弟改动保留（partial-committed）；replan 步骤完成后 run 可 Completed 并发布 | |
| ○ | agent 执行中产生待办，待办全部完成后继续对话 | 底部待办横条出现并在完成后消失 | |
| ○ | 批准一个多步骤计划（如"整理近期新闻成 HTML 时间线"）并观察执行 | 侧边栏步骤随模型每次 `todos_complete` 即时更新（不是执行结束才一次性跳完）；侧边栏可见时底部横条不重复列出计划步骤，`Ctrl+G` 收起侧边栏后横条恢复完整步骤 | |
| ○ | 同上，观察 Plan 阶段 | 每次模型请求都带 `[Budget] web N/5 · sub-agents M/3` 用量行（用到第 4 次起出现"剩 1 次"预警）；第 6 次联网调用不再自动执行，而是弹出审批确认，批准后执行、拒绝后模型收到拒绝结果并转向提交计划；采集型任务的计划只确认范围，采集本身作为 Build 步骤；Build 不重复检索计划里已写明的事实 | |
| ● | PLAN 模式提交计划后立刻观察（模型是否继续调用工具） | 提交成功后该 run 的后续工具调用一律被拒，run 很快自然结束，随后弹出计划审批选择器，不出现“提交后仍持续调用/反复重提” | |
| ● | PLAN 模式提交计划后、审批前强杀进程，重启并恢复该会话 | 重启后计划直接回到可审批状态（弹出审批选择器），而不是永久无响应 | |
| ● | agent 流式输出/运行期间按 Tab | 工作模式不切档（状态栏模式不变）；run 结束后再按 Tab 恢复 Build → Plan → Goal 循环 | |
| ○ | 各模式下执行 `/permissions`（无参），再执行 `/permissions plan` | 无参显示当前模式派生档位；`plan` 被拒绝并提示用 `Tab` 切模式，不留半状态 | |
| ○ | 交互审批模式下执行 `/loop <任务>` | 报错并提示先切自主权限，不替用户放权 | |
| ○ | 切自主权限后执行带 `--check` / `--max` 的 `/loop` | 每轮完整 run，退出码 0 判通过，达上限停止后给出结论 | |
